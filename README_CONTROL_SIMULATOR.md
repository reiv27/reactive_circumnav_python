# План Python-стенда для исследования управления

> Проектный документ, написанный до реализации. Актуальное описание стенда и инструкция по использованию — в [README.md](README.md). Прототип `python_sim/`, на который ссылается текст, удалён из дерева и остаётся в истории git (коммит `109a779`).

## Цель

Цель новой части репозитория — получить не просто анимацию движения робота, а воспроизводимый стенд для control engineering. На нём должно быть удобно:

- изучать кинематику машины Дубинса;
- проектировать и сравнивать законы управления;
- видеть разницу между состоянием объекта, измерением и оценкой состояния;
- исследовать дискретизацию, насыщение, задержки и шум;
- проверять гибридные алгоритмы с переключением режимов;
- проводить серии экспериментов и сравнивать их по численным метрикам;
- позднее подключить CasADi/acados, не переписывая весь симулятор.

Старая симуляция остаётся историческим прототипом. Новый стенд разрабатывается отдельно в пакете `src/circumnav`.

## Основные инженерные принципы

### Разделение ответственности

Каждая физическая или алгоритмическая сущность находится в отдельном модуле:

```text
сценарий
   │
   ├── мир и препятствия
   ├── истинная модель объекта
   ├── модель привода и ограничения
   ├── модель датчика
   ├── оценивание состояния
   ├── закон управления
   └── критерии остановки
            │
            ▼
        симулятор
            │
            ▼
      журнал эксперимента
            │
            ▼
       метрики и графики
```

Регулятор не должен обращаться напрямую к истинному состоянию мира, когда в эксперименте предусмотрен датчик. Симулятор знает ground truth, а контроллер получает только измерение или оценку состояния.

### Явные единицы и соглашения

Во всём новом коде используются единицы SI:

- расстояние — метры;
- время — секунды;
- линейная скорость — метры в секунду;
- угол — радианы;
- угловая скорость — радианы в секунду.

Положительное направление поворота — против часовой стрелки. Угол курса нормализуется в диапазон `[-pi, pi)`.

### Воспроизводимость

Каждый стохастический сценарий должен иметь явный `seed`. Конфигурация эксперимента сохраняется вместе с результатом. Построение графиков и анимаций выполняется после симуляции по журналу и не влияет на динамику.

## Модель машины Дубинса

Состояние объекта:

```text
x = [p_x, p_y, theta].
```

Управление:

```text
u = [v, omega].
```

Непрерывная кинематика:

```text
dp_x/dt = v cos(theta),
dp_y/dt = v sin(theta),
dtheta/dt = omega.
```

Для постоянного управления на интервале используется точное решение, а не шаг Эйлера. При `omega != 0`:

```text
p_x(k+1) = p_x(k) + v/omega * [sin(theta + omega*dt) - sin(theta)],
p_y(k+1) = p_y(k) - v/omega * [cos(theta + omega*dt) - cos(theta)],
theta(k+1) = theta(k) + omega*dt.
```

При `omega = 0` используется прямолинейное движение. Благодаря этому численная ошибка базовой кинематической модели не маскирует ошибки закона управления.

Позднее будет добавлена модель приводов первого порядка:

```text
tau_v * dv/dt = v_cmd - v,
tau_omega * domega/dt = omega_cmd - omega.
```

Она позволит исследовать model mismatch, запаздывание и отличие командной скорости от фактической.

## Временная организация

Симулятор поддерживает раздельные периоды:

- интегрирования или распространения состояния;
- обновления регулятора;
- обновления датчика;
- логирования.

Между обновлениями регулятора команда удерживается постоянной — zero-order hold. На первом этапе реализованы шаг модели и период управления. Периоды датчика и логирования будут добавлены вместе с сенсорным контуром.

Последовательность замкнутого цикла:

```text
измерение → оценка состояния → регулятор → ограничение команды
     ↑                                      │
     └──────── мир ← объект управления ◄────┘
```

Порядок операций фиксируется явно, чтобы избежать скрытого сдвига на один такт.

## Законы управления

Каждый регулятор реализует общий интерфейс:

```python
controller.reset(initial_state)
command = controller.compute(time, state_or_estimate)
```

Первым реализуется пропорциональный регулятор курса:

```text
e_theta = wrap(theta_ref - theta),
omega_cmd = Kp * e_theta.
```

Он выбран как минимальный учебный пример, на котором видны:

- знак обратной связи;
- нормализация углов;
- насыщение угловой скорости;
- влияние `Kp`;
- влияние периода управления;
- установившаяся ошибка и время переходного процесса.

После него реализуется реактивный гибридный регулятор обхода препятствий. Его состояния, условия переходов, гистерезис и минимальное время пребывания в режиме будут явными объектами, а не разбросанными условиями внутри симуляционного цикла.

## Модель датчика

Первая модель датчика будет идеальной геометрической моделью круговой видимости из `README_SENSOR_MODEL.md`. Она должна возвращать только реальные точки препятствий и явно сообщать об отсутствии измерения.

После проверки закона управления появится отдельная модель лидара:

- конечное угловое разрешение;
- минимальная и максимальная дальность;
- шум дальности и азимута;
- пропуски;
- задержка;
- ограниченная частота обновления.

Оба датчика будут иметь одинаковый интерфейс. Это позволит отличать проблемы закона управления от артефактов сенсорной модели.

## Логирование и метрики

В журнале эксперимента должны храниться:

- время;
- истинное состояние;
- измеренное и оценённое состояние;
- запрошенное управление;
- управление после ограничений;
- режим гибридного регулятора;
- опорные точки и служебные ошибки;
- события столкновения и завершения.

Базовые метрики:

- длина траектории;
- финальная и RMS-ошибка;
- минимальная дистанция до препятствия;
- интегральное управление;
- доля времени в насыщении;
- число переключений режимов;
- время достижения цели;
- наличие столкновения.

Большие JSON-файлы и отдельные кадры анимации не являются основным форматом результатов. Численные данные будут сохраняться в компактном виде, а визуализации строиться из них отдельно.

## Тестирование

Обязательные тесты первого уровня:

1. `omega = 0` даёт прямую линию.
2. Постоянная ненулевая `omega` даёт окружность радиуса `v/omega`.
3. После полного оборота объект возвращается в исходную точку с заданной точностью.
4. Угол всегда нормализован.
5. Ограничитель не пропускает команды за допустимые границы.
6. Регулятор курса уменьшает угловую ошибку.
7. Периоды симуляции проверяются на согласованность.

Далее добавляются тесты геометрии, датчиков, событий, гибридных переходов и регрессионные сценарии.

## Запуск первого эксперимента

Из корня репозитория:

```bash
PYTHONPATH=src python3 -m circumnav.examples.heading_control
```

Сохранение временных рядов:

```bash
mkdir -p simulation_output
PYTHONPATH=src python3 -m circumnav.examples.heading_control \
    --output simulation_output/heading_control.npz
```

Запуск тестов без автоматически подключаемых системных плагинов `pytest`:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=src \
    python3 -m pytest -q -p no:cacheprovider
```

После установки пакета в виртуальное окружение через `pip install -e .` переменная `PYTHONPATH` не требуется.

Первый пример намеренно не строит графики внутри цикла. Он возвращает `SimulationResult`, который содержит согласованные временные ряды состояния, запрошенного и приложенного управления и признака насыщения. Это станет единым источником данных для будущих графиков, анимаций и сравнения регуляторов.

Параметры первого опыта можно менять из командной строки. Например, для исследования влияния коэффициента усиления и периода дискретизации:

```bash
PYTHONPATH=src python3 -m circumnav.examples.heading_control \
    --gain 0.5 \
    --control-period 0.10 \
    --initial-heading-deg -90 \
    --desired-heading-deg 120
```

Все параметры эксперимента также собраны в `HeadingControlScenario`. Новый опыт можно определить обычным Python-кодом, не меняя модель объекта, симулятор или регулятор.
