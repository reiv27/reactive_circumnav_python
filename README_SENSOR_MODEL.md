# Геометрическая модель круговой области восприятия

> Проектный документ, написанный до реализации; описанная здесь модель реализована в `circumnav.sensors.circular`. «Текущая симуляция» в тексте — это удалённый прототип `python_sim/` (история git, коммит `109a779`).

## Назначение

В текущей симуляции круговой датчик реализован как набор равномерно распределённых лучей. Каждый луч либо заканчивается в точке пересечения с препятствием, либо в точке на максимальной дальности. Затем среди этих точек выбираются две опорные точки, используемые законом управления.

Такой подход близок к симуляции 2D-лидара, но для исследования самого закона навигации физическая модель лидара не обязательна. Вместо неё можно использовать идеальный круговой датчик видимости, который работает непосредственно с геометрией препятствий и возвращает только реальные точки их границ.

Цель предлагаемой модели — сохранить существующую логику переключения состояний `C` и `G`, но убрать зависимость от количества лучей и не считать концы пустых лучей препятствиями.

## Основная идея

Пусть:

- `r` — положение робота в глобальной системе координат;
- `theta` — ориентация робота;
- `R_sensor` — максимальная дальность восприятия;
- `P1` — ближайшая к роботу видимая точка препятствия;
- `V` — центр виртуального поворотного диска;
- `P2` — другая видимая точка препятствия, ближайшая к `V`.

Вместо дискретного сканирования по углам датчик рассматривает части границ препятствий, попавшие в круг

```text
||q - r|| <= R_sensor.
```

Первая опорная точка определяется как

```text
P1 = argmin ||q - r||,
```

где минимум берётся по видимым точкам границ препятствий.

После этого по существующему правилу строится центр поворотного диска `V`. Вторая опорная точка определяется как

```text
P2 = argmin ||q - V||,
```

но из множества кандидатов предварительно исключается геометрическая окрестность `P1`.

Условие перехода из состояния `C` в состояние `G` остаётся прежним:

```text
||V - P2|| < ||V - P1||.
```

При переходе сохраняется `V` как `v_A`. Условие возврата в `C` также может продолжать использовать взаимное положение `v_A`, текущих `P1`, `P2` и робота.

## Почему это не лидар

Модель не воспроизводит вращение лазера, фиксированное угловое разрешение или время последовательного сканирования. Она описывает идеальное всенаправленное восприятие границ препятствий в круговой области.

Такой датчик можно назвать:

- `OmnidirectionalRangeSensor`;
- `CircularVisibilitySensor`;
- `GeometricRangeSensor`.

Эта абстракция удобна для проверки математического закона управления. Позднее её можно заменить моделью реального лидара, камеры глубины или массива дальномеров, не меняя интерфейс навигационного алгоритма.

## Поиск ближайшей точки на отрезке

Для препятствия, заданного отрезком `[a, b]`, ближайшая к точке `x` точка вычисляется аналитически:

```python
ab = b - a
t = np.dot(x - a, ab) / np.dot(ab, ab)
t = np.clip(t, 0.0, 1.0)
closest = a + t * ab
distance = np.linalg.norm(closest - x)
```

Для поиска `P1` в качестве `x` используется положение робота `r`. Для поиска `P2` используется центр поворотного диска `V`.

Перед сравнением необходимо проверить, что найденная точка находится в пределах `R_sensor` и видима из положения робота.

## Поиск ближайшей точки на эллипсе

Точка повёрнутого эллипса может быть записана параметрически:

```text
e(t) = center + Rot(angle) * [a*cos(t), b*sin(t)],
```

где `a` и `b` — полуоси эллипса.

Ближайшая к произвольной точке `x` точка находится решением задачи

```text
minimize ||e(t) - x||.
```

Для симулятора допустим комбинированный способ:

1. просмотреть конечный набор значений `t` на интервале `[0, 2*pi)`;
2. выбрать лучший небольшой интервал;
3. уточнить минимум одномерной оптимизацией;
4. проверить дальность и видимость результата.

Для `P1` минимизируется расстояние до `r`, а для `P2` — расстояние до `V`.

## Видимость и перекрытие препятствий

Ближайшая геометрическая точка не всегда видима: её может закрывать другое препятствие. Поэтому для каждого кандидата `q` должна выполняться проверка отрезка `[r, q]`.

Кандидат считается видимым, если на направлении от робота к `q` нет более раннего пересечения с другим препятствием. Иными словами, `q` должна быть первым пересечением на своём направлении.

Если в рассматриваемых сценариях препятствия не перекрывают друг друга, эту проверку можно временно отключить. Однако интерфейс датчика лучше сразу проектировать с признаком видимости.

## Исключение окрестности P1

В текущей реализации окрестность первой точки исключается через диапазон индексов лучей. В геометрической модели индексов нет, поэтому окрестность нужно задавать физически.

Возможные критерии:

```text
||q - P1|| > epsilon_distance
```

или

```text
angular_distance(bearing(q), bearing(P1)) > epsilon_angle.
```

Первый вариант не зависит от углового разрешения датчика. Второй ближе к существующему исключению нескольких соседних лучей. Можно применять оба условия одновременно.

Если требуется искать `P2` именно на другом участке границы, препятствиям и их компонентам следует присвоить идентификаторы. Тогда датчик сможет возвращать не только координату, но и `obstacle_id` и `feature_id`.

## Относительные измерения

Найденные точки хранятся в глобальной системе координат, но закон управления может получать их относительно корпуса робота.

Для точки `p`:

```python
delta_world = p - robot_position

world_to_robot = np.array([
    [ np.cos(theta), np.sin(theta)],
    [-np.sin(theta), np.cos(theta)],
])

point_relative = world_to_robot @ delta_world
distance = np.linalg.norm(point_relative)
bearing = np.arctan2(point_relative[1], point_relative[0])
```

Результат измерения может иметь следующий вид:

```python
measurement = {
    "point_world": point_world,
    "point_relative": point_relative,
    "distance": distance,
    "bearing": bearing,
    "obstacle_id": obstacle_id,
    "visible": True,
}
```

## Предлагаемый интерфейс

```python
class CircularVisibilitySensor:
    def __init__(self, max_range):
        self.max_range = max_range

    def observe(self, robot_pose, obstacles):
        """Возвращает видимые части границ препятствий."""

    def find_primary_point(self, robot_pose, visible_geometry):
        """Находит P1 — ближайшую к роботу видимую точку."""

    def find_secondary_point(
        self,
        robot_pose,
        disk_center,
        primary_point,
        visible_geometry,
    ):
        """Находит P2 — ближайшую к V точку вне окрестности P1."""
```

Датчик должен явно сообщать об отсутствии измерения:

```python
P1 = None
P2 = None
```

Концы области дальности не должны добавляться в список препятствий.

## Интеграция с переключением состояний

Обновление состояния может выглядеть следующим образом:

```python
visible_geometry = sensor.observe(robot.pose, obstacles)
P1 = sensor.find_primary_point(robot.pose, visible_geometry)

if P1 is None:
    # В области восприятия нет препятствий.
    handle_no_obstacle()
else:
    V = calculate_disk_center(robot.position, P1, d + turning_radius)
    P2 = sensor.find_secondary_point(
        robot.pose,
        V,
        P1,
        visible_geometry,
    )

    if state == mode_C:
        if P2 is not None and np.linalg.norm(V - P2) < np.linalg.norm(V - P1):
            state = mode_G
            v_A = V.copy()
    else:
        if P2 is not None and not is_point_in_angle(v_A, P1, P2, robot.position):
            state = mode_C
```

Поведение при отсутствии `P2` должно быть определено отдельно. Безопасный базовый вариант — не выполнять переключение по условию, которое невозможно проверить.

## Моделирование погрешностей

Идеальную геометрическую модель можно постепенно приблизить к реальному датчику:

- добавить шум к дальности и азимуту;
- ограничить максимальную и минимальную дальность;
- ввести вероятность пропуска измерения;
- уменьшить частоту обновления;
- добавить задержку;
- ограничить угловое разрешение только на выходе датчика;
- учитывать плохое отражение от наклонных поверхностей.

Шум желательно добавлять согласованно: после изменения `distance` необходимо заново вычислить координату точки вдоль измеренного направления. Нельзя выбирать точку по зашумлённой дальности, оставляя её координаты незашумлёнными.

## Альтернативные реализации

### Адаптивная угловая трассировка

Если нужен результат, похожий на лазерный скан, лучи можно выпускать не через фиксированный шаг, а в информативных направлениях:

- к вершинам препятствий;
- немного левее и правее каждой вершины;
- по касательным к криволинейным препятствиям.

Для каждого направления сохраняется только первое пересечение. Такой метод приближается к построению видимого контура и использует меньше лучей.

### Карта занятости

Препятствия можно растрировать в occupancy grid, а круговую видимость рассчитывать алгоритмом DDA или ray marching. Это полезно, если навигация в дальнейшем будет работать не с точной геометрией, а с картой.

### Поле расстояний

Для карты можно заранее построить signed distance field. Значение поля даёт расстояние до ближайшей границы, а градиент указывает её направление. Этот вариант особенно удобен для управления, но сам по себе не моделирует перекрытие объектов и полный набор видимых точек.

## Рекомендуемый порядок реализации

1. Ввести общий тип измерения с координатой, дальностью, азимутом и идентификатором препятствия.
2. Реализовать точный поиск ближайшей точки для препятствий-отрезков.
3. Исключить точки максимальной дальности из кандидатов `P1` и `P2`.
4. Заменить исключение `±10` индексов геометрической окрестностью `P1`.
5. Добавить явную обработку отсутствующих `P1` и `P2`.
6. Реализовать поиск ближайшей точки на повёрнутом эллипсе.
7. Добавить проверку видимости и перекрытия.
8. После проверки идеальной модели добавить шум и другие свойства реального датчика.

## Ожидаемый результат

Геометрическая модель сохраняет смысл существующего закона управления, но отделяет его от конкретного типа сенсора. Алгоритм получает настоящие точки препятствий и относительные расстояния до них, а модель восприятия можно независимо менять от идеальной круговой видимости до реалистичного лидара или другого дальномера.
